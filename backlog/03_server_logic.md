# Вертикаль: Серверная бизнес-логика (Ktor / Spring Boot)

## Задача 1. Создание единого технологически независимого ядра (server/common/core)
* Описание: Вынесение сквозной прикладной бэкенд-логики в отдельный общий модуль для повторного использования всеми вариантами серверов.
* Подзадачи:
    - [ ] Создать модуль `shared/[имя_продукта]/server/common/core`.
    - [ ] Объявить в общем ядре интерфейс серверного репозитория данных (на примере `DocsServerRepository`), описывающий необходимые контракты выборки, обновления и каскадной записи.
    - [ ] Написать чистый Kotlin-класс сервиса синхронизации (на примере `SyncService`), инкапсулирующий в себе алгоритм вычисления дельты (разницы данных между клиентом и сервером) на основе присланного `SyncMode`.

## Задача 2. Слой ORM и Баз Данных (SQLite)
* Описание: Проектирование реляционных таблиц бэкенда и реализация серверных репозиториев под конкретные ORM-технологии.
* Подзадачи:
    - [ ] **Реализация Exposed (Ktor-Exposed / Spring-Exposed)**:
        - [ ] Описать объект `DocTable` с полями `id` (AutoIncrement Primary Key), `name` (String), `dateOfDoc` (String/Date).
        - [ ] Описать объект `DocRowTable` с полями `id`, `idDoc` (Foreign Key со стратегией `CascadeOnDelete`), `costType` (String/Enum), `costQuantity` (Double), `costPrice` (Double), `costSum` (Double), `meterReadingStart` (Double), `meterReadingEnd` (Double).
        - [ ] Написать класс реализации интерфейса `DocsServerRepository` из общего ядра, используя SQL-запросы Exposed DSL.
    - [ ] **Реализация Hibernate (Spring-Hibernate)**:
        - [ ] Создать класс `@Entity DocEntity` со связью `@OneToMany(cascade = [CascadeType.ALL], orphanRemoval = true)`.
        - [ ] Создать класс `@Entity DocRowEntity` со связью `@ManyToOne`.
        - [ ] Написать класс реализации интерфейса `DocsServerRepository`, делегирующий вызовы автоматическому интерфейсу `JpaRepository`.
    - [ ] **Реализация SqlDelight на сервере (Ktor-SqlDelight)**:
        - [ ] Подключить к модулю существующий общий слой базы данных `projects.sdk.common.database.sqlDelight.core`.
        - [ ] Настроить инициализацию Java-драйвера `JdbcSqliteDriver` для открытия серверного файла базы данных SQLite.
        - [ ] Написать класс реализации интерфейса `DocsServerRepository`, вызывающий готовые транзакции сгенерированного интерфейса `FunctionsQueries`.

## Задача 3. Сетевой слой REST API и Эндпоинты фреймворков
* Описание: Реализация HTTP-маршрутов и контроллеров, выступающих в роли тонких оберток над единым общим ядром бэкенда.
* Подзадачи:
    - [ ] Интегрировать сериализатор `kotlinx.serialization` для обработки JSON на стороне всех серверов.
    - [ ] **Для Ktor (Exposed и SqlDelight версии)**: Настроить DSL-методы `get`, `post`, `put`, `delete` в функции `configureRouting` с делегированием вызовов в общий `SyncService`.
    - [ ] **Для Spring Boot (Exposed и Hibernate версии)**: Создать классы `@RestController` с аннотациями, вызывающие методы общего ядра через автоинжекцию Spring.
    - [ ] Настроить сквозные контракты онлайн-API (CRUD):
        - [ ] `GET /api/docs` -> Делегирование в ядро -> Возврат списка всех сущностей из БД бэкенда.
        - [ ] `POST /api/docs/list-by-ids` -> Делегирование в ядро -> Возврат массива соответствующих сущностей целиком за один запрос.
        - [ ] `POST /api/docs/save` -> Делегирование в ядро -> Прием новой КМР-модели -> Запись в БД.
        - [ ] `PUT /api/docs/update` -> Делегирование в ядро -> Прием измененной КМР-модели -> Полная перезапись существующей сущности в БД.
        - [ ] `DELETE /api/docs/{id}` -> Делегирование в ядро -> Удаление сущности и связанных строк из БД по `id`.
    - [ ] **Реализация единого эндпоинта синхронизации (`POST /api/sync`)**:
        - [ ] Настроить прием входящего тела запроса, содержащего текущий массив данных клиента (`List<Doc>`) и выбранный режим `SyncMode` (`FULL` или `ID_ONLY`).
        - [ ] Передать данные в общий метод `syncService.calculateDelta(clientList, mode)`.
        - [ ] Обеспечить возврат вычисленной ядром дельты согласно выбранному `SyncMode` (объектами целиком либо списком идентификаторов записей).
