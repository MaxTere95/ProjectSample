# Вертикаль: Клиентский интерфейс (Compose / Decompose)

## Задача 1. Форма создания и редактирования сущности (EditDocScreen)
* Описание: Реализация интерактивного пользовательского интерфейса для заполнения метаданных и динамических строк основной сущности (на примере расчета коммунальных услуг).
* Подзадачи:
  - [ ] Создать текстовое поле ввода для строковых метаданных сущности (`Doc.name`).
  - [ ] Реализовать элемент выбора даты для временных метаданных (`Doc.dateOfDoc`).
  - [ ] Сверстать динамический список или таблицу для отображения вложенных строк (`Doc.tableRows`).
  - [ ] Настроить механизмы добавления и удаления элементов списка на основе перечислений (на примере `UtilityType`).

## Задача 2. Интеграция автоматических вычислений в UI реального времени
* Описание: Реализация реактивного пересчета математической логики приложения непосредственно в момент ввода данных пользователем.
* Подзадачи:
  - [ ] Интегрировать фабричные методы вычислений (на примере `DocRow.createWithCalculations`) в Composable-поля ввода.
  - [ ] Настроить текстовые поля для ввода числовых параметров (показаний счетчиков).
  - [ ] Реализовать моментальное отображение промежуточных вычисленных значений (расхода и сумм) в строках без перезагрузки экрана.
  - [ ] Вывести финальное агрегированное значение (общую сумму) в подвале экрана (через геттер `Doc.totalAmount`).

## Задача 3. Интеграция бизнес-компонентов с Compose-экранами
* Описание: Связывание логики жизненного цикла и состояний Decompose с UI-слоем отображения для обеспечения реактивного обновления интерфейса.
* Подзадачи:
  - [ ] Настроить преобразование стэка навигации Decompose (`component.stack`) в состояние Compose через метод `subscribeAsState` на мастер-экранах.
  - [ ] Настроить преобразование потока состояний (`component.state`) в состояние Compose через метод `collectAsState`.
  - [ ] Реализовать прямую передачу пользовательских событий и кликов из UI-представлений в интерфейсы компонентов (примеры: `component::onClickTab`, `component::onClickDoc`).

## Задача 4. Навигация и обновление экранов списков
* Описание: Реализация сквозного сценария сохранения измененных данных и возврата пользователя на актуализированный экран списков.
* Подзадачи:
  - [ ] Настроить вызов персистентного метода `DocsRepository.saveDoc` при отправке формы редактирования.
  - [ ] Применить метод Decompose-навигатора `replaceCurrent` или `pop` для корректного закрытия экрана формы.
  - [ ] Перевести экран списков (на примере `DocsListScreen`) на отображение реальных полей данных сущности (`dateOfDoc`, `name`, `totalAmount`) вместо черновых технических ID.
