# Вертикаль: Сетевая интеграция (Ktor Client)

## Задача 1. Реализация удаленного источника данных (Remote Data Source)
* Описание: Проектирование и написание прикладного сетевого сервиса, поддерживающего точечные онлайн-операции (CRUD) и единый механизм сквозной синхронизации для вычисления и докачки недостающих данных.
* Подзадачи:
    - [ ] Создать класс реализации удаленного источника данных (на примере `DocsRemoteDataSource`) в слое сетевой логики клиента.
    - [ ] Внедрить настроенный экземпляр `HttpClient` из инфраструктурного модуля `SDK:client:network:ktor:core`.
    - [ ] **Блок онлайн-взаимодействия (CRUD)**:
        - [ ] Реализовать метод получения всех записей (HTTP GET), запрашивающий актуальный массив данных с сервера.
        - [ ] Реализовать метод пакетного получения записей (HTTP POST), запрашивающий массив конкретных сущностей по переданному списку их идентификаторов.
        - [ ] Реализовать метод создания сущности (HTTP POST), обеспечивающий отправку новой сериализованной КМР-модели (на примере `Doc`) в теле запроса.
        - [ ] Реализовать метод обновления сущности (HTTP PUT), обеспечивающий передачу измененной КМР-модели на server для полной перезаписи существующей записи.
        - [ ] Реализовать метод удаления сущности (HTTP DELETE), обеспечивающий передачу идентификатора сущности непосредственно в пути URL.
    - [ ] **Единый механизм синхронизации (State Sync)**:
        - [ ] Создать перечисление `SyncMode` с режимами `FULL` (сервер возвращает недостающие на клиенте данные объектами целиком) и `ID_ONLY` (сервер возвращает только идентификаторы записей, которых не хватает клиенту).
        - [ ] Реализовать сетевую функцию сквозной синхронизации (на примере `suspend fun sync(localData: List<Doc>, mode: SyncMode)`), выполняющую единственный HTTP-запрос к бэкенду.
        - [ ] Интегрировать сетевой вызов в прикладной репозиторий данных, реализовав автономный метод `fun sync(mode: SyncMode)`, который самостоятельно запрашивает слепок локального кэша из базы данных и вызывает сетевую функцию `sync(localData, mode)`:
            - При режиме `FULL`: обработать полученный от сервера список недостающих объектов `Doc` и сохранить их в локальную базу данных.
            - При режиме `ID_ONLY`: обработать полученный от сервера список идентификаторов записей, которых не хватает клиенту, и пакетно загрузить их за один запрос через CRUD-слой.
