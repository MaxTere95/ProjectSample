# Вертикаль: Документация, лицензирование и стандартизация

## Задача 1. Создание технического руководства (README.md)
* Описание: Разработка главного руководства по развертыванию, кастомизации и использованию универсального KMP-шаблона.
* Необходимые данные:
    * Техническое описание слоев архитектуры (системный SDK, прикладной Shared, исполняемые Apps).
    * Пошаговая инструкция по замене демонстрационного модуля калькулятора на собственную бизнес-логику.
    * Команды CLI для сборки клиентских платформ (Android, JVM Desktop) и запуска трех бэкенд-серверов.

## Задача 2. Настройка двойного лицензирования и стандартов SPDX
* Описание: Юридическое оформление кодовой базы с интеграцией машиночитаемых стандартов идентификации лицензий.
* Необходимые данные:
    * Файл `UNLICENSE` в корне проекта со стандартным текстом отказа от авторских прав.
    * Файл `LICENSE-MIT` в корне проекта со стандартным текстом лицензии MIT.
    * Текстовый заголовок `// SPDX-License-Identifier: MIT OR Unlicense` в первой строке каждого исходного Kotlin-файла.
    * Раздел в `README.md` с указанием выражения SPDX: `SPDX-License-Identifier: MIT OR Unlicense`.

## Задача 3. Стандартизация код-стайла и контрибьютинга
* Описание: Настройка правил форматирования кода для обеспечения консистентности репозитория при работе разных разработчиков.
* Необходимые данные:
    * Файл `.editorconfig` в корне проекта с фиксацией отступов (4 пробела для Kotlin), кодировки UTF-8 и правил `trim_trailing_whitespace`.
    * Файл `CONTRIBUTING.md` с описанием правил оформления веток Git, формата сообщений коммитов (Conventional Commits) и создания Pull Request.

## Задача 4. Автоматическая генерация API-документации (Dokka)
* Описание: Настройка плагина Dokka для сборки интерактивного HTML-справочника по кодовой базе на основе комментариев в коде.
* Необходимые данные:
    * Подключение плагина `org.jetbrains.dokka` в корневом `build.gradle.kts`.
    * Конфигурация таски `dokkaHtml` для сканирования модулей слоев SDK и Shared.
    * Добавление раздела в `README.md` с инструкцией по запуску генерации справочника через консольную команду **gradle dokkaHtml**.

## Задача 5. Создание шаблонов для платформы GitHub
* Описание: Разработка стандартизированных форм взаимодействия с репозиторием шаблона для сторонних разработчиков.
* Необходимые данные:
    * Каталог `.github/ISSUE_TEMPLATE/` с файлами `bug_report.md` (форма сообщения о баге) и `feature_request.md` (форма предложения фичи).
    * Файл `.github/PULL_REQUEST_TEMPLATE.md` с чек-листом для проверки кода перед слиянием (прохождение тестов, соответствие код-стайлу, наличие заголовков SPDX).

## Задача 6. Документирование скриптов автоматизации проекта
* Описание: Разработка руководства по использованию, назначению и кастомизации встроенных CLI-скриптов автоматизации.
* Необходимые данные:
    * Инструкция по запуску PowerShell скриптов `.ps1` на операционной системе Windows.
    * Инструкция по выдаче прав `chmod +x` и запуску Bash скриптов `.sh` на операционных системах macOS и Linux.
    * Описание синтаксиса и назначения конфигурационного файла `.dumpignore` для фильтрации генерируемых дампов проекта.
    * Добавление раздела в `README.md` с подробным описанием существующих утилит:
        * `dump_project` — сканирует структуру репозитория, отсекает бинарные кэши `build/`, `.gradle/`, `.idea/` на основе правил из `.dumpignore` и собирает весь валидный исходный код проекта в один текстовый файл для проведения сквозного аудита архитектуры.
        * `dump_gradle_config` — изолированно собирает только файлы конфигурации сборщика (`build.gradle.kts`, `settings.gradle.kts`, `gradle.properties`, `libs.versions.toml`), позволяя быстро верифицировать билд-граф, плагины и иерархию зависимостей без анализа исходного кода фич.
