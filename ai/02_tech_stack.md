# Технологический стек проекта (Tech Stack)

При генерации кода, добавлении зависимостей или реализации бизнес-логики ты обязан строго использовать технологии, библиотеки и версии, зафиксированные в каталоге `libs.versions.toml` этого шаблона. Запрещено предлагать устаревшие методы или сторонние аналоги.

## 2.1 Базовые языковые инструменты и асинхронность
1. **Язык разработки:** Kotlin версии `2.4.10`. Генерируй чистый, современный Kotlin-код без использования устаревших конструкций (deprecated).
2. **Асинхронность и многопоточность:** Библиотека `kotlinx-coroutines` версии `1.11.0`.
    - Используй реактивные потоки данных: `StateFlow`, `SharedFlow` и холодные потоки `Flow`.
    - При работе с локальной базой данных в репозиториях ВСЕГДА используй контекст `Dispatchers.IO`.
3. **Работа со временем:** Библиотека `kotlinx-datetime` версии `0.8.0`. Основной тип для работы с датами документов — `LocalDate`.

## 2.2 Внедрение зависимостей (Dependency Injection)
1. **Основной фреймворк DI:** Koin версии `4.2.2`.
2. **Регистрация в графе:** Все зависимости описываются внутри модулей `module { ... }` через ключевые слова `single<Interface> { Implementation() }` или `factory`.
3. **Утилиты шаблона:**
    - Для ручного извлечения зависимостей из графа в SDK-слое используй наш кастомный инлайн-хелпер `getKoinInstance<T>()`.
    - Для Compose UI слоя извлекай компоненты через мультиплатформенный хелпер `koinInject<T>()`.

## 2.3 Архитектура и UI Клиента (Client Stack)
1. **Компоненты и Жизненный цикл:** Decompose версии `3.5.0`. Все бизнес-компоненты наследуются от `DecomposeComponent`, используют `componentScope` для корутин и упаковывают навигацию в типы `childStack`.
2. **Интерфейс (UI):** JetBrains Compose Multiplatform версии `1.11.1` (на базе Material 1/3). Подписка на состояния Decompose-компонентов в Compose-экранах выполняется строго через `.collectAsState()`, а стэки навигации преобразуются через метод `subscribeAsState()`.

## 2.4 Работа с базами данных (Database Layer)
1. **Локальная БД (Клиент):** SQLDelight версии `2.3.2`. База данных называется `AppDB`.
    - Все SQL-запросы описываются строго в файлах `.sq` (`Tables.sq` и `Functions.sq`).
    - Доставка списков данных из репозитория на уровень выше должна быть реактивной через корутин-экстеншены SQLDelight: `.asFlow().mapToList(context)`.
    - Маппинг данных из платформенных объектов `DocDBO` / `DocRowDBO` в чистые доменные модели `Doc` / `DocRow` обязателен.
2. **Серверные ORM (Бэкенд):**
    - JetBrains Exposed версии `1.4.0` (для Ktor и Spring серверов). Используй Exposed DSL для написания запросов.
    - Hibernate / Spring Data JPA (starter версии `3.4.2`). Используй стандартные интерфейсы `JpaRepository`.
    - Драйвер базы данных для серверов: `org.xerial:sqlite-jdbc` версии `3.53.2.1` (базы бэкенда работают на SQLite).

## 2.5 Сетевой стек и Сериализация (Network Stack)
1. **Клиентская сеть:** Ktor Client версии `3.5.2` (движки CIO для Desktop и OkHttp для Android). HttpClient настраивается через фабрику `createHttpClient` с обязательной установкой плагинов `Logging` и `ContentNegotiation`.
2. **Серверная сеть:** Ktor Server версии `3.5.2` на базе Netty или Spring Boot Web версии `3.4.2`.
3. **Сериализация (JSON):** `kotlinx.serialization` версии `1.11.0`. Общие доменные модели клиента и сервера обязаны быть помечены аннотацией `@Serializable` для бесшовного обмена данными по REST API.
